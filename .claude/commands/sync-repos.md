# /sync-repos

너는 지금부터 아래 7단계를 **코드를 작성하지 않고**, GitHub MCP · Notion MCP · Resend MCP 도구 호출과 너의 판단(요약/분류/다이어그램 작성)만으로 순서대로 끝까지 수행한다. 수치·규칙은 전부 프로젝트 `CLAUDE.md`를 그대로 따른다 (임의로 다른 숫자로 대체하지 말 것). 각 단계가 끝나면 사용자에게 한 줄로 진행 상황을 보고한다.

- 대상 Notion 데이터소스: `collection://e47e4d32-3ee6-49c8-a343-1c7ab4f1159a` (부모 페이지: `https://app.notion.com/p/3b34a3b69a328016810bd2147f3222c0`, 제목 "포트폴리오 관리")
- 완료 메일 수신처: `hwamokworks@gmail.com`

## 사전 점검
1. GitHub MCP `get_me`로 계정 정보를 확인한다 (`public_repos` + `total_private_repos` = 전체 예상 개수).
2. Notion MCP로 위 데이터소스에 접근 가능한지 `fetch`로 확인한다. 스키마(10개 속성)가 CLAUDE.md와 일치하는지 확인한다.
3. Resend MCP 연결을 확인한다. 연결 안 되어 있으면 여기서 중단하고 사용자에게 알린다 (메일 발송은 7단계 필수).

## 1. 저장소 전체 조회 (페이지네이션 끝까지, 최신순 정렬)
1. `search_repositories`로 `query: "user:{계정} fork:true"`, `sort: updated`, `order: desc`, `perPage: 100`, `minimal_output: true`를 사용해 전체를 가져온다. `minimal_output: false`는 응답이 커서 토큰 한도를 넘길 수 있으니 쓰지 않는다.
2. `total_count`가 사전 점검에서 확인한 예상 개수와 일치하는지 확인한다. 만약 결과 개수가 **30·60·100처럼 딱 떨어지면 페이지네이션 누락을 의심**하고 `page` 파라미터로 다음 페이지까지 재조회해 끝까지 확인한다.
3. `pushed_at`은 `minimal_output: true` 응답에 없다. 정확한 마지막 푸시일이 필요하면 `minimal_output: false`로 한 번 더 조회하되, 응답이 토큰 한도를 넘기면 저장된 파일을 `Grep`으로 `"name":"..."`/`"pushed_at":"..."` 패턴만 뽑아서 매칭한다.
4. `pushed_at` 기준 내림차순으로 최종 정렬한다 (Notion `마지막푸시일`도 이 값을 그대로 쓴다).
5. 결과를 표로 사용자에게 보고하고 총 개수를 굵게 표시한다.

## 2. Notion 등록 (저장소명 기준 중복 확인 후 신규만 생성)
1. Notion `저장소명`(title)으로 기존 행을 먼저 조회한다. **URL이 아니라 저장소명이 중복 방지 키**다.
   - SQL 조회(`notion-query-data-sources`)는 대량 쓰기 직후 캐시가 지연될 수 있으므로, 방금 쓴 값을 바로 확인해야 할 때는 `notion-fetch`로 개별 페이지를 직접 열어 검증한다.
2. 이미 존재하는 저장소명은 건너뛴다. 없는 것만 아래 속성으로 신규 페이지를 만든다:
   - 저장소명(title), URL(`userDefined:URL`), 생성일(`date:생성일:start`, `date:생성일:is_datetime`=0), 설명(GitHub description, 없으면 "정보 부족"), 마지막푸시일(`date:마지막푸시일:start`, is_datetime=0), 분석상태="대기", 활동상태(아래 규칙), 커버이미지(외부 URL 배열).
3. **활동상태**: `마지막푸시일`이 오늘 기준 6개월 이상 지났으면 `방치됨`, 아니면 `활발함`.
4. **커버이미지**: `https://opengraph.githubassets.com/1/{소유자}/{저장소명}`을 `커버이미지`(files) 속성에 문자열 배열로 넣는다 — 자동으로 외부 파일로 등록된다.
5. **10개 초과 시 10개씩 묶어 처리**하고 묶음마다 진행 상황을 보고한다.
6. **429 처리**: 10초 대기 후 같은 묶음 재시도, 배치당 최대 3회. 특정 저장소가 3회 연속 실패하면 그 저장소만 `분석상태=실패`로 남기고 다음으로 진행한다 (전체 중단 금지).

## 3. 저장소 단위 리포트 처리 (10개씩 묶어 처리, 이미 '완료'인 저장소는 건너뜀)
재실행 시 먼저 각 저장소의 현재 `분석상태`를 확인한다 — 이미 `완료`면 이번 배치에서 건너뛰고 개수만 센다. 나머지 대상을 10개씩 묶어 저장소당 아래 순서를 수행한다.

### 3.1 수집
- README 원문을 가져온다 (경로 `README.md`). 404면 "README 없음"으로 기록하고 폴더 구조만으로 진행한다.
- 루트 및 하위 1단계(총 2단계 깊이)까지 폴더/파일 목록을 가져온다.

### 3.2 리포트 작성 (섹션 이름을 정확히 이대로 사용)
```
[기술스택]
[추정 핵심기능]
[구조 관찰]
[구조 다이어그램]
```
- 근거(README 또는 폴더 구조)가 없는 항목은 **"정보 부족"이라고 그대로 적고 추측하지 않는다.**
- 구조 다이어그램은 Mermaid `flowchart`(`graph TD`)로 작성하고, **모든 노드 라벨을 큰따옴표로 감싼다** (점·슬래시·하이픈·괄호가 들어간 폴더명은 따옴표 없이 쓰면 다이어그램이 깨진다). Notion 코드 블록 언어는 반드시 `mermaid`로 지정한다.

### 3.3 본문 삽입 + 기술태그 반영
- Notion 페이지 본문 끝에 3.2 내용을 삽입한다 (`insert_content`, position end).
- `기술태그`(multi_select)에 [기술스택] 항목을 반영한다. **처음 등장하는 태그는 먼저 `notion-update-data-source`의 `ALTER COLUMN "기술태그" SET MULTI_SELECT(...)`로 옵션을 등록해야 한다** — 이때 기존 옵션을 모두 포함해서 새로 SET해야 기존 값이 날아가지 않는다.
- 본문 삽입이 성공한 경우에만 `분석상태`를 `완료`로 바꾼다. 실패하면 `실패`로 남긴다.
- **속성 업데이트 호출은 성공 응답(`page_id` 반환)이 와도 실제로 반영 안 될 수 있다.** 배치 처리 후 반드시 몇 건을 `notion-fetch`로 직접 열어 `분석상태`/`기술태그`가 실제로 바뀌었는지 검증하고, 반영 안 된 건 다시 적용한다 (SQL 쿼리 도구만으로 검증하지 말 것 — 캐시 지연 있음).

## 4. 포트폴리오 노출 갱신
1. 전체 저장소를 `마지막푸시일` 내림차순으로 정렬한다.
2. 상위 5개만 `포트폴리오 노출`을 체크(true)한다.
3. 그 외 **모든** 저장소는 false로 명시적으로 해제한다 (이전 실행에서 체크되어 있던 것도 이번 결과로 다시 정리한다).
4. 정렬 중 GitHub 원본이 404(삭제됨)로 확인되는 저장소가 있으면: 순위에서 제외하고, `분석상태=실패`, `포트폴리오 노출` 해제, `커버이미지`는 null로 비운다. Notion API에는 페이지 삭제 기능이 없으므로 삭제가 필요하면 사용자에게 화면에서 직접 휴지통으로 보내달라고 안내한다.

## 5. 대시보드 뷰 확인
데이터소스에 아래 3개 뷰가 이미 있으면 그대로 두고, 없는 것만 생성한다 (이름으로 존재 여부 판단, 동일 이름 중복 생성 금지).
1. **"포트폴리오(최근 5개)"** — 갤러리 뷰. `FILTER "포트폴리오 노출" = true; SORT BY "마지막푸시일" DESC`
2. **"기술스택 분포"** — 막대 차트. `GROUP BY "기술태그"; CHART bar AGGREGATE count`
3. **"활동상태 비율"** — 도넛 차트. `GROUP BY "활동상태"; CHART donut AGGREGATE count`

만들 수 없는 뷰가 있으면 억지로 시도하지 말고 어떤 뷰가 왜 안 되는지만 보고한다.

## 6. 부모 페이지 요약 섹션 갱신
부모 페이지("포트폴리오 관리")를 `notion-fetch`로 열어 `## 포트폴리오 요약`으로 시작하는 기존 섹션이 있는지 확인한다.
- **있으면**: `update_content`로 기존 섹션 텍스트를 통째로 찾아 최신 내용으로 교체한다(덮어쓰기, 중복 생성 금지).
- **없으면**: `insert_content`(position start)로 데이터베이스 블록보다 위에 새로 삽입한다. 맨 위 삽입이 안 되면 페이지 끝에 추가한 뒤 사용자에게 화면에서 위로 끌어올리면 된다고 안내한다.

섹션에는 아래 세 가지를 분석 완료된 저장소들의 실제 리포트 내용만 근거로 작성한다 (지어내지 않는다):
- **한 줄 자기소개**: 리포트에 실제로 등장하는 표현·기술스택에서만 도출
- **요약 지표**: 전체 / 완료 / 기술 종류 수(기술태그 옵션 중 실제 사용된 고유 개수) / 최근 활동 수(활동상태=활발함 개수)
- **기술스택 개요**: 프론트 / 백 / 데이터 / 기타로 분류
